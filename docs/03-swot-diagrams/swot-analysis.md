# SWOT-анализ

Проект: веб-приложение «Бюро путешествий» (Travel World)

---

## Матрица

| Сильные стороны (S) | Слабые стороны (W) |
|---|---|
| Данные хранятся в базе и не теряются при перезагрузке | Одна база SQLite — не рассчитана на большую нагрузку |
| Готовая админ-панель Django без отдельной разработки | Нет оплаты и бронирования, только витрина |
| Пароли хранятся в виде хеша, сессии на стороне сервера | Нет подтверждения почты при регистрации |
| Три уровня доступа: гость, пользователь, администратор | Поиск ищет только по названию и описанию, без фильтра по цене |
| Отзыв отправляется без перезагрузки страницы | Нет своего дизайна, интерфейс собран на Bootstrap |
| Адаптивная вёрстка работает на телефоне | Нет писем и уведомлений |

| Возможности (O) | Угрозы (T) |
|---|---|
| Перевод на PostgreSQL при росте числа записей | Утечка данных при работе с `DEBUG = True` в реальной среде |
| Добавление бронирования и оплаты | Спам в отзывах без модерации и капчи |
| Фильтры по цене, длительности, рейтингу | Потеря базы: `db.sqlite3` — один файл, нужны резервные копии |
| REST API и мобильное приложение | Медленная выдача каталога при большом числе фотографий |
| Рассылка новых туров по подписке | Загрузка посторонних файлов через поле фото |
| Личный кабинет с историей заявок | Зависимость Bootstrap от внешнего CDN |

## Выводы

Сильная сторона проекта в том, что почти вся типовая работа —
пользователи, сессии, админ-панель, работа с базой — закрыта
средствами Django, поэтому силы ушли на предметную часть.

Главная слабость — проект остаётся витриной: посмотреть тур можно,
купить нельзя. Это ближайшее направление развития.

Из угроз самая реальная — отзывы без модерации. Пока закрыта только
тем, что администратор видит все отзывы в админ-панели и может
удалить лишние.
