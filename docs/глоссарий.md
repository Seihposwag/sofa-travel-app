## Django и веб-разработка

**Django** — каркас для разработки веб-приложений на Python. Даёт
готовые решения для работы с базой данных, пользователями,
шаблонами и админ-панелью.

**MTV (Model — Template — View)** — способ разделения кода в Django.
Model описывает данные, Template отвечает за внешний вид,
View связывает их: берёт данные и передаёт шаблону.

**Модель (Model)** — класс Python, который описывает таблицу в базе
данных. Одно поле класса — один столбец таблицы.

**Представление (View)** — функция, которая обрабатывает запрос
и возвращает ответ. В проекте одна функция обслуживает одну страницу.

**Шаблон (Template)** — HTML-файл с пропусками, куда Django
подставляет данные при формировании страницы.

**Маршрут (URL pattern)** — правило, связывающее адрес страницы
с функцией-представлением. Задаётся в файлах `urls.py`.

**Приложение (App)** — часть проекта Django со своими моделями,
представлениями и шаблонами. В проекте два приложения: `tours`
и `users`.

**ORM** — слой, который переводит операции над объектами Python
в SQL-запросы. Позволяет работать с базой без написания SQL вручную.

**Миграция (Migration)** — файл с описанием изменений структуры базы.
Django создаёт их по моделям и применяет к базе командой `migrate`.

**Наследование шаблонов** — приём, при котором общая часть страницы
(шапка, меню, подвал) хранится в одном файле `base.html`,
а остальные страницы вставляются внутрь него.

**Серверный рендеринг** — сборка HTML-страницы на сервере.
Браузер получает готовую разметку, а не собирает её сам.

**Форма (Form)** — класс Django, который проверяет присланные
пользователем данные до записи в базу.

**Пагинация** — разбиение длинного списка на страницы.
В проекте каталог выводится по шесть туров.

**Админ-панель** — встроенный в Django раздел управления данными
по адресу `/admin/`. Собирается автоматически по описанию моделей.

**Команда управления (Management command)** — свой скрипт, который
запускается через `manage.py`. В проекте это `seed_demo`.

## Базы данных

**SQLite** — база данных, которая хранится в одном файле
и не требует отдельного сервера. Входит в состав Python.

**Первичный ключ (Primary Key, PK)** — поле, однозначно
определяющее запись. Django создаёт его автоматически с именем `id`.

**Внешний ключ (Foreign Key, FK)** — поле, ссылающееся на запись
в другой таблице. Например `country_id` в таблице туров.

**Индекс** — служебная структура, ускоряющая поиск по полю.
В проекте индексы стоят на дате создания, признаке публикации,
направлении и авторе тура.

**Нормальные формы (1НФ, 2НФ, 3НФ)** — правила организации таблиц,
исключающие дублирование данных. База проекта приведена к 3НФ.

**CASCADE** — при удалении записи удаляются все связанные с ней.
Так удаляются отзывы вместе с туром.

**PROTECT** — запрет удаления записи, на которую есть ссылки.
Так защищено направление, у которого есть туры.

**SET NULL** — при удалении записи ссылка на неё обнуляется.
Так тур остаётся в базе после удаления автора.

## Пользователи и безопасность

**Аутентификация** — проверка, что пользователь тот, кем себя
называет: сверка логина и пароля.

**Авторизация** — проверка, есть ли у пользователя право
на конкретное действие.

**Сессия** — способ запомнить вошедшего пользователя. Сервер
хранит данные о входе, а браузеру отдаёт идентификатор сессии
в cookie.

**Cookie** — небольшая порция данных, которую браузер хранит
и отправляет обратно серверу при каждом запросе.

**Хеш пароля** — необратимое преобразование пароля. В базе
хранится результат преобразования, а не сам пароль.

**CSRF** — атака, при которой сторонний сайт отправляет запрос
от имени вошедшего пользователя. Django защищается специальным
токеном в каждой форме.

**XSS** — атака через вставку постороннего кода в текст на странице.
Шаблонизатор Django экранирует вывод и не даёт коду выполниться.

**`login_required`** — декоратор Django. Если сессия не открыта,
перенаправляет на страницу входа.

**`is_staff`** — признак у пользователя, открывающий доступ
к админ-панели.

**AbstractUser** — заготовка модели пользователя в Django.
Модель проекта наследуется от неё и добавляет свои поля.

## Клиентская часть

**AJAX** — обращение к серверу из JavaScript без перезагрузки
страницы. В проекте так работают отзывы, избранное и подсказки поиска.

**JSON** — текстовый формат передачи данных. В нём сервер
отвечает на AJAX-запросы.

**`fetch`** — встроенная в браузер функция отправки запросов
к серверу.

**Bootstrap** — библиотека готовых стилей и компонентов
для оформления интерфейса.

**Адаптивная вёрстка** — вёрстка, которая перестраивается
под ширину экрана и остаётся читаемой на телефоне.

## Предметная область

**Направление (Country)** — страна или регион, к которому относится
тур. Играет роль категории.

**Тур (Tour)** — туристическое предложение: название, описание,
цена, длительность, фотография.

**Отзыв (Review)** — текстовое мнение пользователя о туре.

**Избранное (Favorite)** — личный список туров пользователя.

**Черновик** — тур без признака «Опубликован». Виден только автору
и администратору, в каталог не попадает.
